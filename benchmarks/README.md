# 基准测试

记录**可复现的性能数据**，而不是"感觉更快"。这是技术记录里最有说服力的部分之一。

约定：`raw/` 存放原始采集数据（已 gitignore），仓库只提交**脚本 + 结果摘要 + 结论**。

## 计划中的对比

| 主题 | 指标 | 阶段 |
|---|---|---|
| zenbedded vs Micro-ROS | 端到端延迟、抖动、内存占用、开发复杂度 | 一（W6） |
| 官方插件 vs 自定义控制器 | 路径跟踪误差、控制精度 | 二（W14） |
| 默认 NavFn vs 自定义 A* | 路径平滑度、规划耗时 | 二（W20） |
| 仿真 vs 真机 | 端到端延迟、里程计精度 | 三（W28） |

## 目录约定

每个基准一个子目录，至少包含：

```
benchmarks/<主题>/
├── run.sh        # 采集脚本，参数化，可重复执行
├── analyze.py    # 统计与出图
└── README.md     # 环境、方法、结果表、结论、局限
```

## 必记的元数据

- 硬件（CPU / MCU 型号、主频）与操作系统
- ROS 2 发行版与构建类型（**Debug 还是 Release** —— 对延迟影响巨大）
- 样本数与统计量（均值之外必须给标准差或分位数，只看均值会骗人）
- 延迟类数据必须说明**时钟来源与同步方式**
